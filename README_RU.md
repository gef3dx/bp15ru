# БЮРО путешествий — Python / Django

Самостоятельный проект, перенесённый из `BURO_travel_FINAL_Netlify(1).zip`.
Исходный сайт: https://2026-buro-1.netlify.app/

## Что входит

Сохранены семь основных страниц, их тексты, порядок разделов, фотографии,
логотипы, CSS, интерактивная схема маршрутов, карусель, фильтры программ,
вкладки, адаптивное меню и PDF-презентация. Изображения, PDF и CSS перенесены
без изменения байтов. Из существующего JavaScript заменён только блок отправки форм.

Маршруты: `/`, `/bureau/`, `/ossetia/`, `/dmc-mice/`, `/programs/`,
`/exclusive/`, `/contacts/`. Сохранены `/success.html` и оформление ошибки 404.
Ссылки вида `/bureau/index.html` перенаправляются на `/bureau/`.

Обе формы (`trip-request` и `contact-request`) отправляют данные на
`/inquiries/submit/`. Заявки сохраняются в базе; их можно просматривать,
искать, отмечать как обработанные и дополнять внутренними заметками в `/admin/`.

**Это перенос существующего сайта, а не внедрение редактора всего контента.**
Тексты и фото страниц редактируются в `templates/website/` и `static/`.
В административной панели предусмотрено управление заявками, не страницами.
Новые программы, отзывы, платежи, личные кабинеты и интеграции CRM не добавлялись.

**Публикация не выполнялась. Действующий сайт Netlify не изменён.**

## Требования

Python 3.12 или 3.13, доступ к PyPI при первой установке. Используется ветка
Django 5.2 LTS с нижней границей 5.2.17; совместимые обновления устанавливаются
из `requirements.txt`. Node.js и сборка frontend не нужны.

Для локального запуска используется SQLite. Для сервера предусмотрены
Gunicorn + WhiteNoise и необязательный PostgreSQL.

## Быстрый запуск на Windows

1. Распакуйте архив в обычную папку. Не запускайте файлы непосредственно из ZIP.
2. Установите Python 3.12/3.13 с Python Launcher.
3. Дважды щёлкните `start_windows.bat`.
4. Когда появится сообщение о запуске сервера, откройте http://127.0.0.1:8000/.

Скрипт создаст виртуальное окружение `.venv`, установит зависимости,
создаст локальный `.env` с уникальным случайным ключом и применит миграции.
Готовый `.env` не перезаписывается. Для остановки сервера нажмите Ctrl+C.
Если окно установки показывает ошибку сети, сначала обеспечьте доступ к PyPI.

Чтобы создать администратора, откройте терминал в папке проекта и выполните:

```bat
.venv\Scripts\python.exe manage.py createsuperuser
```

Логин и пароль выбираете самостоятельно. Готовых паролей в архиве нет.
Административная панель: http://127.0.0.1:8000/admin/.

## Ручной запуск

Windows, командная строка:

```bat
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe scripts\setup_local.py
.venv\Scripts\python.exe manage.py createsuperuser
.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Linux / macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/setup_local.py
python manage.py createsuperuser
python manage.py runserver 127.0.0.1:8000
```

Или используйте `bash start.sh`. В обоих случаях зависимости устанавливаются
из интернета, а не включены в ZIP. Файл базы создаётся при первом `migrate`;
тестовых заявок и аккаунтов в поставке нет.

## Формы и уведомления

Заявка считается принятой только после сохранения в базе. Для этого SMTP
не нужен. При успешном сохранении открывается исходная страница «Спасибо».

Предусмотрены CSRF-проверка, серверная валидация, скрытое поле против ботов,
ограничение размера запроса, лимит отправок и защита от повторного сохранения
при повторной отправке одного запроса. При ошибке JavaScript не очищает форму.
Данные проверяются на сервере независимо от браузерных ограничений.
Срок действия формы — 48 часов; затем страницу необходимо обновить.

`INQUIRY_EMAIL_ENABLED=false` по умолчанию: **письма не отправляются**, заявки
видны в админке. Чтобы включить уведомления, укажите в закрытом `.env`:

```dotenv
INQUIRY_EMAIL_ENABLED=true
INQUIRY_RECIPIENTS=адрес-получателя@ваш-домен.ru
DEFAULT_FROM_EMAIL=адрес-отправителя@ваш-домен.ru
EMAIL_HOST=сервер-вашего-почтового-провайдера
EMAIL_PORT=587
EMAIL_HOST_USER=имя-пользователя
EMAIL_HOST_PASSWORD=пароль-приложения
EMAIL_USE_TLS=true
EMAIL_USE_SSL=false
```

Это образец, а не готовые учётные данные. Для SMTPS-порта 465 обычно
используются `EMAIL_USE_SSL=true` и `EMAIL_USE_TLS=false` — точные параметры
берите у своего почтового провайдера. Эти два режима нельзя включать одновременно.

При ошибке SMTP заявка остаётся в базе, статус уведомления становится
«Ошибка отправки». Повторить отправку можно действием в админке или командой:

```bash
python manage.py retry_inquiry_emails --limit 50
```

Чтобы включить также старые заявки, поступившие до настройки почты:

```bash
python manage.py retry_inquiry_emails --include-disabled --limit 50
```

Статус «Передано почтовому серверу» означает успешное принятие SMTP-сервером,
но не подтверждение доставки во входящие адресата. Получение настоящего
письма необходимо проверить после подключения вашего SMTP.

В заявке сохраняются только переданные поля, текст согласия и время получения.
Для ограничения частоты используется HMAC IP-адреса с временным окном;
сам IP-адрес не записывается в таблицу ограничений. Очистка истёкших окон:

```bash
python manage.py clear_inquiry_rate_limits
```

Запускайте эту команду ежедневно через планировщик сервера. Строки заявок
она не удаляет. Лимит по умолчанию — 10 отправок за 10 минут с одного адреса.
Это базовая защита, не замена защите от распределённых атак.

Без JavaScript доступна обычная форма на странице «Контакты». Модальное окно,
интерактивная карта и фильтры требуют JavaScript, как и в исходной версии.

## Публикация на сервере

Не загружайте этот архив в Netlify Drop как статическую папку: приложение
должно запускаться как Python/Django на совместимом сервере.

1. Установите `requirements-production.txt` в виртуальное окружение сервера.
2. Скопируйте `.env.example` в закрытый `.env`, заполните параметры.
3. Обязательно задайте `DJANGO_DEBUG=false`, уникальный `DJANGO_SECRET_KEY`,
   точные `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS` и `SITE_URL`.
4. Настройте базу, резервное копирование и постоянное хранилище.
5. Выполните миграции и сборку статических файлов:

```bash
python -m pip install -r requirements-production.txt
python manage.py migrate --noinput
python manage.py collectstatic --noinput
python manage.py createsuperuser
python manage.py check --deploy
```

Ключ можно сгенерировать командой и перенести результат в `.env`:

```bash
python -c "import secrets; print(secrets.token_urlsafe(64))"
```

Далее запустите за HTTPS reverse proxy:

```bash
gunicorn config.wsgi:application --bind 127.0.0.1:8000 --workers 1 --threads 4 --timeout 30
```

`runserver` используется только для разработки. Файлы `wsgi.py` и `asgi.py`
включены; основной пример развёртывания — WSGI/Gunicorn.

`deploy/nginx.conf.example` содержит пример для HTTPS. Замените домен и пути
сертификатов. Прокси должен перезаписывать `X-Forwarded-Proto` и `X-Real-IP`,
а сервер приложения не должен быть доступен напрямую из интернета.
Только при выполнении этих условий включайте `DJANGO_TRUST_PROXY_HEADERS=true`.
По умолчанию подставленным клиентом proxy-заголовкам приложение не доверяет.
Без доверенных proxy-заголовков все посетители за одним прокси могут попасть
в общий лимит его IP-адреса.

HSTS по умолчанию отключён (`DJANGO_SECURE_HSTS_SECONDS=0`), поэтому
`check --deploy` предупредит о HSTS до его настройки. После проверки HTTPS
задайте сначала небольшой срок, затем согласованный постоянный срок.
Не включайте `includeSubDomains`/`preload`, пока не проверены все поддомены.

`SITE_URL` формирует sitemap и ссылку на sitemap в robots.txt. В примере
сохранён исходный `https://bp15.ru`; замените его, если основной домен другой.
Контактная ссылка `bp15.ru` в футере сохранена как часть исходного содержания.
Стили, логотипы и документы обслуживает WhiteNoise после `collectstatic`.

Google Fonts подключается извне точно так же, как в исходнике. При
недоступности этого сервиса используются резервные шрифты исходного CSS.
Файлы внешних шрифтов в архив не добавлялись. Остальные фотографии и
PDF-презентация лежат внутри проекта и не зависят от Netlify.

### PostgreSQL

Установите `requirements-production.txt`, задайте `DB_ENGINE=postgresql`
и заполните `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`,
`DB_SSLMODE`. Затем выполните `migrate`. Переключение настроек **не переносит**
уже полученные заявки из SQLite автоматически; миграцию существующих данных
нужно выполнить отдельно, с резервной копией.

### Docker — дополнительный вариант

Включены `Dockerfile` и `compose.yaml`. Сначала заполните `.env` для выбранного
режима, затем:

```bash
docker compose up --build -d
docker compose exec web python manage.py createsuperuser
```

Пример использует постоянный volume `buro_data` для SQLite и слушает только
`127.0.0.1:8000` на хосте. Для публикации нужен HTTPS-прокси на хосте.
В режиме `DJANGO_DEBUG=false` без HTTPS-прокси будет редирект на HTTPS,
поэтому простое открытие HTTP-порта не является настройкой production.
Для локальной HTTP-проверки создайте `.env` командой `scripts/setup_local.py`.
Не выполняйте `docker compose down -v`, если нужно сохранить заявки:
эта команда удаляет том данных. При использовании PostgreSQL требуется
отдельный доступный сервер базы; compose не создаёт его автоматически.

## Проверки

Подробное описание фактически выполненных проверок — `docs/QA_RU.md`.
Не путайте наличие тестов в проекте с подтверждением их запуска.

После установки зависимостей:

```bash
python manage.py test --settings=config.test_settings
python manage.py makemigrations --check --dry-run --settings=config.test_settings
python scripts/check_assets.py
```

Дополнительная проверка только клиентской отправки (не требует Django;
Node.js нужен лишь для этой проверки, не для работы сайта):

```bash
node scripts/check_form_transport.cjs
```

Тесты Django настроены на отдельную временную базу в памяти и тестовую почту:
не читают реальные заявки и не отправляют настоящие письма.

Перед реальным запуском дополнительно проверьте формы через ваш HTTPS-домен,
админку, поступление письма и восстановление базы из резервной копии.
Условия обработки персональных данных и сроки их хранения в организации
не определялись в рамках технического переноса; исходный текст согласия сохранён.

## Структура

- `config/` — настройки, URL, WSGI/ASGI.
- `website/` — страницы, обработчик форм, модели, миграции, админка и тесты.
- `templates/website/pages/` — семь страниц сайта.
- `templates/website/includes/` — общий футер и модальная форма.
- `static/` — исходные изображения, стили, JavaScript, PDF-презентация.
- `scripts/` — локальная инициализация и проверка целостности ресурсов.
- `docs/` — информация об исходнике, контрольные суммы, результаты проверок.
- `deploy/` — образец конфигурации сервера.
